## 控制逻辑

- 新增独立插件 `rmcs_yaw_identification`；复用原硬件接口、ValueCollector 和
  RMCS `PidCalculator` 类（复制原计算实现，去掉实验未使用的 ROS 参数辅助函数；
  来源为 rmcs_core/src/controller/pid/pid_calculator.hpp，GPL-3.0-only）。
- 必须保留 referee::Status，供硬件超级电容命令读取裁判系统供电状态。
  实验插件同时提供 0 W 的超级电容充电功率上限，补齐硬件依赖，不加载底盘运动控制器。
- 启动为 OFF，两轴输出零。无 DR16 输入，不会因 launch 自动运动。
- 默认 `allow_arm: false`。在 OFF 状态手动小幅抬起并观察控制台 `pitch_deg`：
  若数值从约 +5°向 0°、−5°变化，可确认当前负向抬升目标的方向；
  若数值反而增大，必须重新确定 pitch 目标和机械限位，不能直接解锁。
  确认方向后在 `identification.yaml` 的 `yaw_experiment.ros__parameters`
  中把 `allow_arm` 改为 `true`，再启动实验。重新运行 prepare.py 会恢复为锁定。
  本车 10 月 4 日手动验证：抬起从 +4.86°降至 −36.19°，放下回到 +4.52°。
  本次实验使用的 `identification.yaml` 已设为 `allow_arm: true`；重新运行
  `prepare.py` 会恢复为锁定，需重新核对方向并解锁。运行中的进程不会热加载配置。
- 终端 `arm` 后，yaw 保持此刻位置，pitch 从当前角度按 5°/s 缓慢趋近 -18°。
在本车 pitch 坐标约定中负角为抬头；这是相对 yaw 框架的编码器角度，
  底盘须水平固定。首次要检查实际方向和零位，不能仅凭数值认定实际抬头角。
  2026-10-05 的实测在编码器约 -8.97° 时世界 pitch 仅约 +3.4°，yaw 轴没有转动。
  因而目标调整为编码器 -18°，预计世界 pitch 接近 +10°。实际世界 pitch
  仍需现场核对；低于 +8° 时插件不启动或继续 yaw 扫频，并令 yaw 扭矩为零。
- LkMotor 的原始 pitch 角度为 0–360°；例如 350°按有符号角处理为 −10°。
  控制台显示的 `pitch_deg` 已归一化，CSV 中原始电机角度仍保持原值。
- pitch 用原车串级 PID 增益和世界坐标下的重力补偿；`/tf` 提供发射架的世界
  pitch，编码器角度仍用于目标和行程判断。总力矩限制为 ±4.5 Nm，另有限制
  扭矩变化率。配置超过 RMCS 为 MG4010Ei10 记录的 4.5 Nm 最大力矩参考值时，
  插件拒绝启动。是否足以抬升和保持仍需实机确认。
- pitch 距目标小于 1.5°且角速度小于 0.05 rad/s，持续 1 s 后进入 READY。
  稳定判定使用 50 ms 低通后的 pitch IMU 角速度；PID 和超速保护仍使用原始值。
  READY 失去稳定条件时立即回到 RAISING，避免服务接受 sweep 后又因内部计时
  不满足而丢弃命令。控制台显示 `completed=1` 才表示完整完成了一轮扫频。
  然后 `sweep` 才会执行 yaw 扭矩扫频。pitch 偏离或世界 pitch 低于 +8° 时
  立即取消本次扫频并恢复保持，
  不自动重新扫频。
- yaw 相对使能位置限制在 ±8°，最终扭矩 ±3.6 Nm；当前扫频幅值 0.96 Nm、
  0.2→3 Hz、20 s，先确认反馈后再调幅值。
- `hold` 只取消扫频，两轴继续保持；`off` 让两轴卸力并复位故障。
- 控制台每 0.2 s 发心跳，1.5 s 未收到心跳会进入故障并把两轴扭矩清零。
  角度越界、超速、过热、pitch 抬升超时或持续接近扭矩上限而无位移也会清零。
  卸力和断电时 pitch 都可能落下，必须有机械支撑/不会干涉的落点。
- 当前原硬件接口没有逐电机反馈时间戳。首次使能要求两台电机温度反馈大于零，
  但这只能排除尚未收到首包，不能检测之后所有反馈冻结；心跳只检测操作终端。

## 构建（不启动硬件）

在已加载 C 车 ROS 环境的远端部署容器中：

```bash
cd ~/yaw_identification
bash build-addon.bash
source addon_install/setup.zsh  # 当前远端终端是 zsh；bash 用 setup.bash
python3 prepare.py --source /rmcs_install/share/rmcs_bringup/config/deformable-infantry-omni-c.yaml
python3 run.py identification --check-only
```

插件通过独立 ament 索引注册，不修改原 plugins.xml。不使用 sync-remote 覆盖整车安装。
build-addon.bash 只构建本目录插件并运行无硬件状态机测试。
构建还会生成 `addon/compile_commands.json`，供 VS Code 的 clangd 识别本插件
的 C++23、头文件路径和 ROS 依赖。首次构建后若 `engine.hpp` 仍显示旧诊断，
在 VS Code 执行 “clangd: Restart language server”。

## 操作（准备好实车后人工执行）

原常驻服务必须已停止，一次只运行一个 rmcs_executor。底盘和 pitch 要有支撑，
明确知道怎么切断电机电源。无 DR16 时，不应把网络终端当作硬件急停。

远端终端 A：

```bash
service rmcs stop
cd ~/yaw_identification
source addon_install/setup.zsh
python3 run.py identification
```

另开一个本地开发容器终端，`ssh-remote` 进入同一远端容器；终端 B：

```bash
cd ~/yaw_identification
source addon_install/setup.zsh
python3 console.py
```

先观察 state=0、pitch_deg 的实际数值。输入 `arm` 回车会抬起 pitch；
观察方向与支撑情况。state=2 后才能输入 `sweep`。实验结束会回到保持状态。
`hold` 为取消扫频/继续托住，`off` 为卸力，`quit` 为卸力并退出。
故障后先确认原因，输入 `off` 复位，再决定是否 `arm`。

2026-10-04 实机待命启动检查：依赖配对成功，约 6 s/2900 个采样点均为 OFF，
两轴命令扭矩为零。退出时已安装的 librmcs_core.so 在 USB 回调/StatusMonitor
路径仍出现段错误，属于尚未修复的退出问题。结束有力保持前须先支撑 pitch，
通过控制台 off 确认扭矩清零，再关闭程序；不能把进程退出当作已经验证可靠的停机方式。

状态：0 OFF，1 RAISING，2 READY，3 SWEEP，4 FAULT。
故障：1 心跳超时；2 无效反馈/更新间隔过长；3 pitch 越界；4 超速；5 yaw 越界；
6 温度达到 65°C；7 pitch 抬升超过 10 s；8 pitch 接近扭矩上限且无明显位移超过 1 s。
故障 8 不能区分力矩不足和机械卡死，不应仅凭此故障判定机构堵转。
控制台同时显示 `pitch_cmd_Nm`（请求扭矩）、`pitch_fb_Nm`（电机反馈扭矩）
和 `motor_rad_s`。两种扭矩要对照看；请求到达限幅不代表电机实际达到限幅。
10 月 4 日首次抬升，命令约 −3 Nm、角度从 +5.44°到 +2.94°后停住并触发超时；
当时未记录电机反馈扭矩，不能据此单独判定为负载过大。随后一次试验记录到
反馈约 −3 Nm、转速接近 0、温度约 34°C，并触发卡住保护；因此下一次仅将
试验限幅小步提高至 3.5 Nm，保留卡住保护。10 月 4 日后续试验中，手动协助抬升
使 pitch 角速度达到 -0.817 rad/s，超过 0.8 rad/s 的超速门槛，触发故障 4 并立即
清零扭矩；这不是电机自行失去力矩。该次自动抬升时实际只请求到约 -3.0 Nm，
因此将速度环负向输出下限由 -1.0 调为 -1.5 Nm，让命令可到达原有的 3.5 Nm
总限幅。后续从约 -5° 自动抬升时，输出只有约 -2.94 Nm，停在 -6.8°，10 秒后
触发故障 7 并清零；于是又将速度环 Kp 从 2.0 调到 5.0，使大角度误差时能达到
原定 3.5 Nm 限幅。试验时应在 OFF 状态手动将发射架置于约 -10°并始终扶住，
输入 arm 后确认进入 READY、且反馈力矩足以保持，再逐渐松手；OFF、超时、
堵转或其他故障都会立即卸力，必须用手或机械支撑防止下落。不要在运行中快速
搬动。

随后从约 -2° 执行 arm，pitch 到约 -5.6° 后停住：命令持续 -3.5 Nm，电机反馈
约 -3.4 至 -3.5 Nm，电机转速为 0；随后触发故障 8，输出按保护逻辑归零。
这证明目前的配置确实用到了设定的最大试验力矩，仍无法在该位置继续抬升。
用户随后确认机构没有卡滞，本次按抬升力矩不足处理。当前将试验总限幅从
3.5 提到 4.0 Nm，速度环 Kp 从 5.0 提到 7.0，负向输出下限从 -1.5 改为
-2.0 Nm。速度参考仍限于 ±0.25 rad/s：在零速、大角度误差时可请求约
-1.75 Nm 的速度环力矩，加上约 -2.4 Nm 的重力补偿后，能达到新的 -4.0 Nm
总限幅。只改总限幅而保留 Kp=5.0 会使请求仍受限于约 -3.7 Nm。
此调整尚未实机验证能否抬升和保持；故障 8 的无位移保护仍保留。
参数在插件启动时读取，修改 identification.yaml 后需重启实验进程才生效；
无需重新生成整车配置。故障时必须有支撑，避免下落。

原车程序能正常抬升，但 4.0 Nm 实验在约 +1.4° 处再次触发故障 8。核对
`merge/deformable` 后发现原车角度 PID 和速度 PID 没有实验先前的 ±0.25 rad/s
参考限制及 ±4.0 Nm 总力矩限制；原车重力补偿使用世界 pitch。现已恢复原车
pitch PID 增益、扩大内部速度参考范围并接入 `/tf` 计算世界 pitch，同时保留
4.5 Nm 总限幅及无位移保护。CSV 新增限幅前请求值和世界 pitch。
`pitch_fb_Nm` 为电流换算估计，不能当作独立力矩测量。

随后实机从编码器 +4.5° 抬到 -8.93°，保持约 9 s；世界 pitch 从约 -8°
升到 +3.8°，相当于抬起约 12°。旧版以目标 -10° 的严格 1° 误差门槛
判定 READY，实际误差约 1.07°，因而满 10 s 触发故障 7。READY 容差现改为
可配置的 1.5°；当时目标仍为 -10°。稳定时间为 1 s，抬升超时为 10 s。

10 月 5 日第二次完整扫频中，激励达到 ±0.08 N·m，yaw 指令力矩约
[-0.111, +0.116] N·m，电流换算的反馈力矩随之变化，但 20 s 内 yaw 编码器
仅变化约 0.00009 rad。同期世界 pitch 约 +3.4°，低于机械上顺畅转动所需的
约 +10°；所以首先提高实际抬头角并设置 +8° 扫频门槛，暂不把无转动归因
于静摩擦或继续提高 yaw 力矩。实验结束后故障码 1 表示控制台心跳丢失，
会使两轴指令力矩归零。

## 数据与模型

ValueCollector 以 500 Hz 写 `/tmp/c_yaw_ident_<timestamp>.csv`，包括 yaw 命令扭矩、
测量角度/速度/扭矩、pitch 角度和保持扭矩、状态、故障、实际时钟和扫频激励。
重启前复制走日志。分析可在笔记本上进行：

第三次试验的世界 pitch 已达到约 +11.3°。手动助转时 yaw 偏离启动位置
约 8.03°，触发故障码 5（超过 ±8° 行程限制），两轴卸力。随后按要求把扫频
幅值从 ±0.08 提高到 ±0.16 N·m，总力矩上限从 ±0.30 提高到 ±0.60 N·m，
速度环输出限幅从 ±0.20 提高到 ±0.40 N·m。运行中不要手动助转越过行程限制。

随后按要求再次将 yaw 设置提高到上述值的 3 倍：扫频幅值 ±0.48 N·m、
总力矩上限 ±1.80 N·m、速度环输出限幅 ±1.20 N·m。

±0.48 N·m 试验完整运行 20 s，yaw 活动范围约 1.19°。随后按要求再次翻倍：
扫频幅值 ±0.96 N·m、总力矩上限 ±3.60 N·m、速度环输出限幅 ±2.40 N·m。
上限不是恒定输出指令；实际扭矩是速度环输出与扫频激励之和再限幅。

默认扫频幅值为 `0.96 N·m`。首次 `0.01 N·m` 试验和第二次 `0.08 N·m`
试验的 yaw 位移均不足以辨识；两次试验的实际抬头角都不足约 +10°。
分析使用与控制器一致的
`/gimbal/yaw/velocity_imu` 作为角速度，并拒绝 yaw 角度变化小于 `0.001 rad` 的记录。

```bash
python3 -m pip install -r requirements.txt
python3 analyze.py --sweep /path/to/c_yaw_ident_TIME.csv --out analysis_output
```

分析器选择最后一次扫频片段，拒绝故障中断或未结束的片段；旧 SweptFrequencyController
日志也兼容。拟合 `θ̇=ω, ω̇=aω+bu+c`，使用总输出扭矩作输入，不把激励单独当作
电机实际输入。前 70% 拟合，后 30% 单步预测验证。单步误差不能代替完整自由响应
和独立实验验证；闭环噪声、摩擦和饱和会影响估计，不应把第一组参数直接宣称为真实惯量。

## 基线和候选配置的当前范围

`baseline.yaml` / `tuned.yaml` 仍是原车控制器参考配置，保留其遥控依赖；
无 DR16 时 run.py 禁止直接启动这两种模式。它们用于保存原 PID 参数，不是已完成
的无遥控器自动对比实验。应先完成 pitch 保持和 yaw 辨识，再接入可重复目标轨迹，
以实际原控制器和候选控制器分别采集对比数据。不能用本次弱保持环冒充原控制器基线。
